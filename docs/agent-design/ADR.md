# 商品档案 Agent · 架构决策记录（ADR）

> 配套文件：`CONVERSATION_LOG.md`（含逐字对抗样本与推理链）。
> 每条 ADR 格式：状态 / 背景 / 决策 / 理由 / 后果 / 对应证据。

---

## ADR-001 载体从"财务对账"改为"商品档案一致性"

- **状态**：Accepted
- **背景**：初拟"对账领域 agent"，但知识来源于前公司公开文档，业务是借来的；与已有商品域零耦合；可视化挂商品中心会显得突兀。
- **决策**：放弃财务对账业务名，把对账直觉降维进商品域——"生成结果 vs 规则/已有数据"的一致性对账。
- **理由**：作品项目需要第一人称可信度 + 复用全部已有资产（低代码/schema/组件库/后端/商品中心）。"浅"的不是业务，是没看见对抗样本里已有的深。
- **后果**：所有严肃性（匹配分层、规则版本、异常工单、人在环、评测指标）原样移植，但合理性翻倍。
- **证据**：对话第 2-4 轮。

## ADR-002 主干刚性保留，绝不 agent 化

- **状态**：Accepted
- **背景**：现有流程为"固定品类→固定参数→固定提问→规则提取+AI 参数补充→生成schema→模板映射→渲染→入库"。
- **决策**：分步收集、regx 值域校验、options 强制降级、模板映射、渲染、插库——**全部保留不动**，且作为"反例与地基"显式展示。
- **理由**：唯一判据 = "做事路径能否提前写死"。用户路径 100% 可写死，强行 agent 化是技术降级。
- **后果**：作品叙事从"又做了个 agent"翻转为"我知道哪些不该 agent 化"，后者在招聘市场是稀缺信号。
- **证据**：Nova13 对话 + 对抗样本品牌/销售价/规格三处 regx+options 全部兜住。

## ADR-003 agent 边界环位置：收集完 → 生成 schema 前

- **状态**：Accepted
- **背景**：主干收的是封闭槽位；开放语义、否定意图、复合句、业务常识在主干里没有承载位。
- **决策**：只在"信息收齐后、生成 schema 前"插一个 agent 环。上游主干不动，下游渲染不动。
- **理由**：现有 LLM 被放在最末端（生成商品详情），结果是"把脏数据洗成自信文案"——经典幻觉合理化。同一个模型移到上游闸口，从"美化脏数据"变"拦截脏数据"，零成本翻转位置。
- **后果**：架构定型为"确定性主干 + agent 边界层"的混合体，企业级真实形态。
- **证据**：对抗样本商品详情段 = 品牌1/¥1/膨化食品 洗成通顺文案。

## ADR-004 agent 环五项职责（按优先级，含两条主动排除）

- **状态**：Accepted
- **背景**：需精确划出 agent 只做"模型结构表达不出来的"。
- **决策**：
  1. **意图分类**：合法值/乱答/否定/缺失/玩笑/复合句；
  2. **否定·缺失正确出口**（最高优先级）：确认跳过/标 pending/阻止上架，杜绝降级污染；
  3. **多槽复合解析** + 跨字段/特殊值承接；
  4. **业务常识校验**：值合理性、时间有效性、字段归属对账；
  5. **否定泛化**：替代硬编码特例。
  - **主动排除**：值域合法性（交 regx）、强制补值（交 options）。agent 抢做这两件即降级。
- **理由**：后两条 regx/options 已做到最优；agent 重复做暴露不懂边界。
- **后果**：agent 边界被钉死为"结构上无处安放的那四件事"，无可争议。
- **证据**：
  - 职责2 ← 最终档案"品牌1/¥1/100g膨化食品"全是降级污染；
  - 职责3 ← "是 最小不知道 单位增量是20 最大无限"被重问后真实意图(20/无限)丢失；
  - 职责4 ← "优惠日期到2016-12-31"格式合法但过期；名称="还没想好"元语言被当数据；
  - 职责5 ← "不返利"→0% 目前靠硬编码特例。

## ADR-005 regx/options/类型/schema = oracle，从"校验用户"翻转为"校验模型"

- **状态**：Accepted
- **背景**：纯聊天 agent 停在 prompt 层的根因是没有 oracle，只能"换个 prompt 再问一遍"。
- **决策**：把已有的 regx / options / 字段类型 / 品类 schema 暴露成**可被模型调用的校验服务**。模型提议 → oracle 裁决 → 不通过带结构化错误回喂重试。
- **理由**：这是 prompt 层到 agent 层的唯一通道，且不引入任何新组件，纯复用。
- **后果**：agent 环真正跳出 prompt 层，且全程建立在你已有的确定性地基上——不心虚。
- **证据**：`create_product_categories.params` 含 `regx{source,flag}/options`。

## ADR-006 "跳出 prompt 层"的三条尺子（作品自检标准）

- **状态**：Accepted
- **背景**：用户担心"改好了也没深度，像多此一举"。
- **决策**：作品任何 agent 模块必须同时满足三条，缺一条即套壳：
  1. 有 **propose→verify→retry** 回路（不是模型一次答完）；
  2. 有 **确定性 oracle** 不信模型（不是让模型自我认证）；
  3. 有 **对抗样本评测** 能跑分、能回归（不是"看起来能用"）。
- **理由**：深度不在领域，在层在不在。
- **后果**：用户手里零件齐 2/3（oracle + 对抗样本都有），只差第 1 条回路结构——"最省力"路线被严格证明。
- **证据**：ADR-005（oracle）+ ADR-007（对抗样本）。

## ADR-007 对抗样本即评测集，禁止编造

- **状态**：Accepted
- **背景**：harness 评测集通常要么编、要么没有；编的没有可信度。
- **决策**：用 Nova13（干净基线样本）+ 食品对抗样本（红队样本）作为评测种子。**逐字保留，禁止改写**。指标：否定·缺失识别率 / 多槽解析正确率 / 污染率(降级塞值) / 特殊值(∞)承接率 / 业务无效检出率。
- **理由**：真实线上对话的对抗样本比任何构造的 benchmark 都硬，且能跑出 before/after 对照。
- **后果**：评测不靠编造，来自用户亲手喂的脏输入。
- **证据**：`CONVERSATION_LOG.md` 第 5 轮逐字对抗样本。

## ADR-008 差异化叙事：不是客服 agent，是"语言模型被 oracle 关进笼子"

- **状态**：Accepted
- **背景**：用户担心"和招聘市场客服 agent 没区别"。
- **决策**：作品主屏**不**展示生成的表单，**展示对抗样本被拦下来的过程**——左原始对抗输入 / 中 agent 提议逐槽被 oracle 纠正 / 下红字对比"纯 regx+降级污染 vs agent环拒绝污染" / 右指标跑分。
- **理由**：客服 agent 浅是因为没 oracle/没评测——它们画不出"被确定性系统纠正"这件事；而你有 oracle 又有对抗集，画得出。前端是此画面的天然主场。
- **后果**：作品从"又一个聊天框"翻到"能证明边界在哪的严肃 agent"——后者在招聘市场几乎空缺。
- **证据**：整场对话 + ADR-005/006/007。

## ADR-009 上下文/记忆外置为项目文件（本 ADR 即此课的产物）

- **状态**：Accepted
- **背景**：本次会话曾因工作区切换"消失"；插件会话按工作区隔离。
- **决策**：高价值上下文（对抗样本原文、推理链、决策依据）必须外置成项目文件；会话内"总结"有损，不可作为高保真续接。
- **理由**：LLM 无持久记忆——你担心我记不住，正是你的 agent 必须设计好外部状态(pending 队列/会话状态/trace日志)的原因。**这条工具插曲本身就是作品的第 10 条课。**
- **后果**：`CONVERSATION_LOG.md` 与 `ADR.md` 是作品"外部记忆层"的第一个 dogfood 实例。
- **证据**：本文件 + 对话第 8 轮。

## ADR-010 未决：事实核查与多 SKU 组合（暂挂）

- **状态**：Deferred / Open
- **背景**：规格候选给了白黑银红黄蓝 × 8/12/16GB × 128/256/512GB，最终只产出"黑色+12GB+128GB"一个组合；型号-规格是否真实存在无人核。
- **决策**：暂挂，待用户回答"是否有合法规格组合表 / 品类可用字段定义(含促销字段)"。
- **理由**：依赖知识库；若没有现成表，5 条命门已足以撑起作品，不硬凑。
- **后果**：不阻塞 ADR-003 的环结构开工。
- **证据**：Nova13 规格段。
