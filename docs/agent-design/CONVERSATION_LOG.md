# 商品档案 Agent 设计 · 会话决策记录

> 用途：本文件为高保真上下文锚点。开新会话时 `@` 本文件与 `ADR.md`，
> 即可接上"为什么这么定"的推理链，而不只是结论。
> 凡标「原文」者为逐字保留的输入样本或关键提问，是评测集的种子，禁止改写。
> 凡标「论证」者为对话中推理步骤的忠实压缩，每一步均保留。

## 第 0 轮 · 初始诉求与误判

**用户原话（节选）**：

> "我是有多年 SaaS 经验的开发者，要做对账领域的 agent，先讨论方案。"

**论证（助手第一轮给出的判断骨架）**：

1. 对账不是"聊天框 + LLM"，应是审计级工作流系统：LLM 只做编排/翻译/解释/异常处理，匹配逻辑保持确定性、可追溯、可测。
2. 给出分层架构：对话层 / 编排层 / 领域服务层 / 数据层。
3. 给出核心切分表：Agent 负责"理解意图、规划、解释、建议"；引擎负责"匹配、规则执行、容差、审计"。
4. 给出 MVP 范围与三条非目标：不自动发布规则、不自动写财务系统、不接自由代码执行。

**当时被默认的假设**（后被推翻）：对账业务本身值得做。

---

## 第 1 轮 · 暴露真实动机：作品项目

**用户原话（节选）**：

> "我没想清楚是否有价值……是用它作为前端转 agent 的作品项目，需要它有竞争力，目前能找到的是前公司公开的对账功能产品文档作为信息参考。"

**论证**：

1. 作品项目的评判标准 ≠ 产品价值。作品看四件事：能否证明具备 Agent 工程能力、是否有真实难点、能否放大独特优势、能否被 30 秒看懂。
2. 选财务对账为载体的三个硬伤：
   - 业务是"借来的"——知识来自文档，不是第一人称踩坑；被追问"容差为何是 0.5% 不是 1%"会暴露。
   - 数据凭空造，且与已有商品域零耦合。
   - 可视化优势没接上——商品中心是商品展示，对账是后台表格。
3. 给出 4 个竞争力维度：编排与状态 / 工具调用可靠性 / 可解释与可审计 / 评测与指标。
4. 给出两个差异化切面：A 可解释的对账工作台、B 自然语言驱动的异常诊断+规则助手。建议 A 为主 B 为辅。

**用户随即补充真实资产，推翻上述载体选择**。

## 第 2 轮 · 用户给出真实资产，方向第一次大翻转

**用户原话（逐字）**：

> "已做好项目：①智能低代码平台（Vue3+TS+pinia+webworker+canvas，AI 多轮对话生成商品档案）；②商品中心（Nuxt3 SSR 预览）；③后端（express+knex+mysql）。
> 生成流程：固定品类→固定参数→固定提问→规则提取+AI 参数补充→生成schema→模板映射→组件库渲染→数据入库。
> 问题：这个过程只设计 token/prompt/context 流程，没到 agent/mcp/harness。业务场景太浅没有转行竞争力，所以想做对账 agent，可视化挂在商品中心一个菜单。"

**论证**：

1. 肯定用户的自诊断"只到 prompt 层"准确——能说出自己缺在哪，已是少数。
2. 但方向选错：为了练开车特意换条陌生山路。技术练到，故事断裂，作品割裂。
3. 给出替代路线：**把已有的固定 pipeline 升级成 agent**。
   - pipeline 与 agent 的本质区别 = 路径能否提前写死。能写死用代码，不能写死才轮到 agent。
   - 用户原流程"每一步都固定"——所以按它**当时的样子**，确实不该 agent 化。
4. 给出 agent/mcp/harness 在该升级里如何"自然长出"。
5. 对账降维：不做银行流水对账，改做"生成结果 vs 规则/已有数据"的**商品档案一致性校验对账**——对账直觉的精华（匹配分层、规则版本、异常工单、人在环、评测指标）可原样移植。

## 第 3 轮 · 用户给出完整干净样本，方向第二次翻转（收回上轮建议）

**用户原话**：提供 Nova13 手机商品完整对话流程。流程中规格"无/空"被重复提示三次，最终用户从 options 降级面板选出 黑色+12GB+128GB。

**用户提问（逐字）**：

> "这个过程只设计 token/prompt/context 流程，没到 agent/mcp/harness……我找不到为什么要它变成 agent 的理由。"

**论证**：

1. 用户的直觉对：在"名称/品牌/价格"这种刚性主干上**强行 agent 化是技术降级**。
2. 助手正式**收回**第 2 轮"把生成改造成 agent"的建议——理由：当时假设输入脏、路径开口；补上这条样本后假设不成立。该更新就更新。
3. 提出 agent 是否值得用的唯一判据：路径能否提前写死。用户路径 100% 可写死。
4. 但把"作品竞争力"重新归位：竞争力不在业务名字，在 4 层（边界判断/混合架构/工程配套/评测harness）。

## 第 4 轮 · 用户提供品类表结构，逐条证据重新定级

**用户提供（逐字核心）**：

> `create_product_categories.params` 为 JSON 数组，每项含 `key/label/regx{source,flag}/options`。
> 服装品类示例：size regx=`XS|S|M|L|XL|XXL`；color regx=`色|color|colour`；material regx=`棉|丝|纤|纺|其他`。
> options 规则：出现降级选项后每项必须选一个，点确定后 skuSummary 即由这组降级选项拼成。
> 现状："不准不会答"，除非问题里有"跳过/不需要"。

**论证（逐条用结构重判上轮证据）**：

1. **证据1（拒答死循环）→ 我说重了，当场修正**。系统有 options 降级，是"无效→追问→降级强制选"，不是死循环。但降级暴露新问题（见下）。
2. **证据2（字段填错位值）**：regx 能判"10 不是是/否"→ 降级；但降级**吞掉**真意图，而非把它归位到"最小订货量"。
3. **证据3（跨字段约束 10/100/1000）**：params 结构上没有"字段间关系"的列。**强命门保留**。
4. **证据4（自由补充"优惠日期"）**：params 是封闭数组，"优惠日期"无处落。**最强命门保留**。
5. **证据5（事实核查/多SKU）**：依赖是否有知识库，暂不算命门。
6. **新增证据1'**：options 降级假设"有值没说准"，对"无/都行/没想好/你看着办"接不住——用户想"没有"被强制必须有。
7. **新增证据7（regx 做不了"提取"）**：用户答"我喜欢红色和蓝色" / "不要棉的要丝" / "这料子滑不滑"，regx 只能判"在不在值域"，不能消歧/处理否定/识别反问。
8. **agent 边界收敛**：agent 环只做"模型结构上表达不出来的"——歧义提取、否定意图、跨字段约束、开放补充对账；**主动排除**"类型/合法性校验"和"强制补值"（agent 抢做这两件是降级）。

### 论证（对对抗样本的逐条分析）

**先给确定性该有的分**：品牌/销售价/规格三处，对抗输入均被 regx 判无效、被 options 降级兜住，垃圾字符没进字段。这三处若换 agent 反而危险（模型可能真把"大城市"读成某种价格语义）。这三处**不主张动**。

**但降级救场的方式，制造了比死循环更隐蔽的问题**——

### 论证核心：降级把"没有/不知道"翻译成了"我确信是 X"

最终档案里 `品牌1/¥1/100g膨化食品` —— **用户从未表达过**。用户表达的是"早饭没吃/大城市/这个产品没有/我不知道"。机制把否定、玩笑、缺失**统统降级强制选了一个合法值**。

| 状态                            | 后果                                              |
| ------------------------------- | ------------------------------------------------- |
| 字段留空 = 数据"缺失"           | 诚实，可回头补                                    |
| 强制降级填值 = 数据"错误且自信" | 撒谎，下游做销售分析/B2B报价/上架会把 ¥1 当真售价 |

→ **agent 环第一职责由"提取准不准"升级为"区分无效与否定/缺失，把后者导到正确出口"**。options 机制在结构上无法做此区分，因为它把所有非合法值都归为"没说准"。此对抗样本里该错配出现 ≥5 次（品牌×3、价格×3、规格×3、名称、最大无限），是高频。

### 论证续：钉死 6 条 regx + 固定流程**结构上**接不住的命门

| 命门               | 样本原话                                 | 为何结构性失效                                                                          | 级别     |
| ------------------ | ---------------------------------------- | --------------------------------------------------------------------------------------- | -------- |
| A 元语言被当数据   | 名称="还没想好"                          | 名称是开放字段，无 regx 值域，"还没想好"长得像正常字符串，**直接通过**入库              | 致命     |
| B 复合句多槽位     | "是 最小不知道 单位增量是20 最大无限"    | 流程假设"一问一答一槽"，**没有"一句话拆多槽"的入口**；重问后用户真实意图(20/无限)被抹掉 | **王炸** |
| C 特殊语义值       | "最大无限"                               | int 字段无 ∞/null 结构位                                                                | 强       |
| D 局部否定         | "最小不知道" / "这个产品没有" / "不返利" | regx 看"在不在值域"，看不出"它在否定/说缺失"                                            | 强       |
| E 否定映射不可扩展 | "不返利"→0%                              | 特例硬编码可写，"不要返利/免返/返个寂寞"泛化写不完                                      | 中强     |
| F 业务常识         | "优惠日期到2016-12-31"                   | 格式合法 ≠ 业务有效；过期日期应告警，regx 无时间/常识位                                 | 强       |

**B 单独强调**：这一句让固定流程"输得彻彻底底"，且不是"难写"是"模型里没这个结构"。把这句放进作品叙事是顶级论据——pipeline 没有多槽并行解析和跨槽否定的概念，这不是 if-else 能堆的。

### 论证续：LLM 现用位置=最危险的末端

唯一真 LLM 在末端"生成商品详情"，结果：把"还没想好/品牌1/¥1/膨化食品"**洗成一段自信、通顺、全错的产品文案**。这是经典的 LLM 被喂垃圾 → 幻觉式合理化。**根因 = 上游校验环缺位**。同一个模型换个位置，从"美化脏数据"变"拦截脏数据"。

### 论证续：意外收获 = 对抗样本即天然评测集
